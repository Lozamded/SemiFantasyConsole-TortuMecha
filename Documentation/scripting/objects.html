Object scripts

Attach a script to a .tortuobject prefab to give a placed instance behavior — an enemy, an NPC, the player controller.

A .tortuobject asset has a script field: a project-relative path (e.g. "scripts/robot.py"). Every scene instance of that prefab runs its own private copy of the script.

The hooks

def init(engine):
    ...        # once, when this instance's script loads

def update(dt):
    ...        # every frame

def draw(engine):
    ...        # exists, but never called for object scripts — see below
draw() is a no-op here The scene renderer draws every object purely from its current animation/frame state — it never calls an object script's draw. Every example object script defines def draw(engine): pass for exactly this reason. Set the sprite frame with instance_api.set_animation() instead of trying to draw manually.

Per-instance isolation: SELF_ID and LINKS

The same prefab (and so the same script file) can be placed many times in a scene — two robots, say. Each placed instance gets its own private module namespace, so ordinary module-level globals are safe per-instance state (this is the "no subclassing" convention mentioned throughout the codebase). Before the script body runs, two globals are injected automatically — no import needed:

GlobalTypeMeaning
SELF_IDstrThis placed instance's scene id.
LINKStuple[str, ...]Ids of other instances this one references, set via the scene editor's object link list (e.g. a robot linked to its own dialogue-icon instance).

Use them bare, straight from module scope:

from tortoisengine import instance_api

def update(dt):
    x, y = instance_api.get_position(SELF_ID)
    icon_id = LINKS[0]
    instance_api.set_position(icon_id, x, y - 20)

instance_api — the only way to reach outside your own script

Object scripts never touch the Scene, the player controller, or GUI layers directly — they go through tortoisengine.instance_api instead, so the same script keeps working whether it runs in TortoiseStudio's preview, TortoisePlayer, or an exported cart.

from tortoisengine import instance_api

Instance position, visuals, state

FunctionBehavior
get_position(instance_id) / set_position(instance_id, x, y)World position, or None if the id isn't found.
set_animation(instance_id, animation)Switch the drawn sprite animation by name — this is how object scripts "draw" (see above).
is_visible / set_visible(instance_id, visible)Show/hide.
is_flip_x / set_flip_x(instance_id, flip_x)Mirror the sprite horizontally. Colliders/hitboxes are not affected.
is_enabled / set_enabled(instance_id, enabled)Disabled instances are skipped for both rendering and collision checks.
custom_var(instance_id, name, default=None)Reads a per-instance custom-variable override set in TortoiseStudio; falls back to default (conventionally the generated CUSTOMVAR_<NAME>_DEFAULT, see below).
prefab_positions(prefab, exclude_id="")World positions of every enabled scene instance of a given prefab path — pass SELF_ID as exclude_id to find only other instances of your own prefab.

Collision queries

FunctionBehavior
tile_solid_at(x, y)True if the world pixel lands on a solid tile in the scene's collision tile layer.
object_solid_at(x, y, exclude_id="")Same, but for solid scene objects (e.g. a wall prefab) rather than tiles.
solid_object_rects(left, right, top, bottom, exclude_id="")The exact AABBs of every solid object intersecting a rect — for a swept collision resolver that needs real edges, not just a point test.
set_object_solid(instance_id, solid)Per-instance solidity override, independent of enabled. Pass None to revert to the prefab's own solid flag — e.g. a brick block that stops blocking the moment it starts breaking, while its own break-timer update() keeps running.

Player-published state

The player controller script publishes its own state once per frame; any other script (HUD, enemies) reads it. Only the player controller should call the setters.

Setter (player controller only)Getter (anyone)
set_player_position(x, y)player_position() -> (x, y)
set_player_crouching(bool)player_is_crouching() -> bool
set_player_hitbox(left, right, top, bottom)player_hitbox() -> tuple | None
set_player_energy(current, max)player_energy() -> (cur, max) | None
set_player_lives(current, max)player_lives() -> (cur, max) | None
set_player_gears(count)player_gears() -> int | None

Cross-script signals

One-shot request/consume pairs for talking between unrelated scripts without a direct reference to each other:

Function pairUsed for
request_dialogue(path) / take_dialogue_request()Ask the dialogue GUI layer to show a dialogues/*.json file.
set_dialogue_active(bool) / is_dialogue_active()The dialogue box reports whether it's currently showing.
request_scene_transition(scene_path) / take_scene_transition_request()Ask the top-level scene driver to switch scenes — e.g. a save/load HUD asking the level script to move on.
request_object_hop(instance_id) / take_object_hop_request(instance_id)Ask one specific instance to play a cosmetic reaction next update.
set_game_paused(bool) / is_game_paused()Global pause flag — gameplay scripts check this and skip their own movement/logic while true.

Generated helpers: scripts/_generated/*_auto.py

Whenever a project is saved in TortoiseStudio, it regenerates a small sidecar module per object/scene (tortoisengine/script_codegen.py). Never hand-edit these files — import from them instead. See How It Fits Together for the full authoring → codegen → runtime loop this is part of; this section is just the field-by-field reference.

from scripts._generated import robot_auto as auto
Generated forConstants it defines
Each object (<name>_auto.py)ANIM_<NAME> per animation, DEFAULT_ANIMATION, COLLIDER_<NAME> per collider, SOLID, ORIGIN, and CUSTOMVAR_<NAME> / CUSTOMVAR_<NAME>_DEFAULT per custom var.
Each scene (<scene>_auto.py)OBJ_<ID> per placed instance, LINKS_<ID> for instances with a link list.
Audio (fixed path scripts/_generated/audio_auto.py)CHANNEL_<NAME> per audio channel, AUDIO_CHANNELS (path→channel dict). See Subsystems.

Collider bounds are resolved this way too, combining the object's declared colliders with its default sprite size and origin — never hand-copy pixel offsets:

obj = load_object(ROOT / "assets/objects/robot.tortuobject")
sprite = load_sprite(ROOT / obj.default_sprite)
x, y, w, h = obj.colliders[0].resolved(sprite.pixel_width, sprite.pixel_height)

A level-driver script

Not every "object script" is a small enemy or NPC — a player controller script (e.g. mechaturtle_player.py) is also just an object script, but a much bigger one: it typically owns its own SceneRenderer, calls load_scene() and instance_api.bind_scene(), and drives renderer.tick() / .render() / .render_overlay() itself each frame from its update/ draw — effectively acting as the level's main.py while also being one placed instance in the scene it's driving.
